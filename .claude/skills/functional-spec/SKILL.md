# 기능명세서

## M1. 인증/권한 모듈

### M1-1. 로그인
- **설명**: 이메일/비밀번호로 Supabase Auth 인증
- **입력**: 이메일, 비밀번호
- **처리**:
  1. Supabase Auth `signInWithPassword` 호출
  2. 인증 성공 시 `users` 테이블에서 role 조회
  3. role별 대시보드로 리다이렉트
    - admin → `/admin/dashboard`
    - store → `/store/dashboard`
    - tailor → `/tailor/dashboard`
    - user → `/my/shop`
- **유효성**: 이메일 형식 검증, 비밀번호 필수
- **에러**: 인증 실패 시 "이메일 또는 비밀번호가 올바르지 않습니다" 표시

### M1-2. 로그아웃
- **설명**: 현재 세션 종료
- **처리**: Supabase Auth `signOut` 호출 → `/` 리다이렉트

### M1-3. 비밀번호 찾기
- **설명**: 등록된 이메일로 비밀번호 재설정 링크 발송
- **입력**: 이메일
- **처리**: Supabase Auth `resetPasswordForEmail` 호출
- **결과**: "비밀번호 재설정 링크가 발송되었습니다" 표시

### M1-4. 비밀번호 변경
- **설명**: 새 비밀번호 설정 (재설정 링크 클릭 후 또는 로그인 상태)
- **입력**: 새 비밀번호, 비밀번호 확인
- **유효성**: 최소 8자, 비밀번호 확인 일치
- **처리**: Supabase Auth `updateUser` 호출

### M1-5. 권한 제어
- **미들웨어 (Next.js)**:
  - 비인증 사용자: `/`, `/forgot-password`만 접근 가능
  - admin 역할: `/admin/**` 접근 가능
  - store 역할: `/store/**` 접근 가능
  - tailor 역할: `/tailor/**` 접근 가능
  - user 역할: `/my/**` 접근 가능
  - 역할 불일치 시 해당 역할의 대시보드로 리다이렉트
- **RLS (Supabase)**: 테이블별 행 수준 보안 정책 적용

### M1-6. 메뉴 관리 (군수담당자)
- **설명**: 역할별 대메뉴/하위메뉴 관리
- **기능**: 메뉴 CRUD, 순서 변경, 역할별 접근 권한 설정
- **메뉴 구조**: Pull-Down 방식 (대메뉴 → 하위메뉴)
- **필드**: 메뉴명, URL, 상위메뉴, 순서, 접근 역할(복수), 사용 여부

## M2. 사용자 관리 모듈

### M2-1. 사용자 목록 조회 (군수담당자)
- **설명**: 전체 사용자 목록을 페이지네이션으로 조회
- **필터**: 역할, 계급, 이름 검색
- **표시 항목**: 이름, 군번(사번), 계급, 역할, 소속, 등록일, 상태

### M2-2. 사용자 개별 등록 (군수담당자)
- **입력**: 이름, 이메일, 역할, 계급, 군번(사번), 소속, 입대일(근무시작일), 진급일, 퇴직예정일
- **처리**:
  1. Supabase Auth에 사용자 생성 (`admin.createUser`)
  2. `users` 테이블에 상세 정보 저장
  3. role=store인 경우 소속 판매소(store_id) 지정 필수
  4. role=tailor인 경우 소속 업체(tailor_id) 지정 필수
- **유효성**: 이메일 중복 검사, 필수 항목 검증

### M2-3. 사용자 일괄 등록 (군수담당자)
- **설명**: 엑셀/CSV 파일 업로드로 다수 사용자 일괄 등록
- **처리**: 파일 파싱 → 유효성 검사 → 개별 등록 반복
- **결과**: 성공/실패 건수 표시, 실패 항목 상세 다운로드

### M2-4. 사용자 정보 수정 (군수담당자)
- **수정 가능 항목**: 이름, 계급, 소속, 진급일, 퇴직예정일, 상태(활성/비활성)
- **비즈니스 규칙**:
  - 계급 변경 시 진급일 필수 입력
  - 진급일 변경 시 일할계산 포인트 추가 지급 트리거 (M5 연계)

## M3. 기초 데이터 관리 모듈

### M3-1. 피복판매소 관리 (군수담당자)
- **기능**: CRUD
- **필드**: 판매소명, 주소, 연락처, 담당자, 사용 여부
- **제약**: 삭제 시 소속 사용자/재고가 있으면 삭제 불가 (비활성만 가능)

### M3-2. 체척업체 관리 (군수담당자)
- **기능**: CRUD
- **필드**: 업체명, 사업자번호, 대표자, 주소, 연락처, 계좌정보, 사용 여부
- **제약**: 삭제 시 등록된 체척권이 있으면 삭제 불가

### M3-3. 배송지 관리 (피복판매소)
- **설명**: 해당 판매소의 직접 배송 가능 지역 관리
- **기능**: CRUD
- **필드**: 배송지명, 주소, 비고
- **제약**: 자신의 판매소 배송지만 관리 가능

## M4. 품목 관리 모듈

### M4-1. 품목 분류 관리 (군수담당자)
- **설명**: 대/중/소 3단계 계층 분류
- **기능**: 분류 CRUD, 계층 이동
- **필드**: 분류명, 상위분류, 단계(1/2/3), 순서, 사용 여부
- **제약**: 하위 분류가 있는 분류는 삭제 불가

### M4-2. 품목 관리 (군수담당자)
- **기능**: CRUD
- **필드**: 품목명, 소분류, 품목유형(완제품/맞춤피복), 단가, 이미지, 설명, 사용 여부
- **비즈니스 규칙**:
  - 완제품: 규격 관리 필수, 재고 관리 대상
  - 맞춤피복: 규격 없음, 주문수량 항상 1, 재고관리 없음, 체척권 발행 대상

### M4-3. 규격 관리 (군수담당자)
- **설명**: 완제품 품목의 규격(사이즈) 관리
- **기능**: 규격 CRUD (품목 상세 페이지 내 인라인)
- **필드**: 규격명(예: 95, 100, 105), 순서, 사용 여부
- **제약**: 재고가 있는 규격은 삭제 불가, 완제품에만 적용

## M5. 포인트 관리 모듈

### M5-1. 포인트 산정 (군수담당자)
- **설명**: 해당 연도 전체 사용자의 피복포인트를 산정 (미리보기)
- **산정 규칙**:
  1. 계급별 기본 금액 적용 (`ANNUAL_POINTS`)
  2. 근무년수 계산: `현재연도 - 입대연도` (1년에 1호봉)
  3. 호봉 추가: `호봉 × 5,000원`
  4. 퇴직예정자: 퇴직예정일까지 일할계산
     - `기본금액 × (1월1일~퇴직예정일 일수) / 365`
  5. 최종 금액 = 기본금액 + 호봉추가 (퇴직예정자는 일할계산 적용)
- **출력**: 사용자별 산정 금액 목록, 총액 합계

### M5-2. 포인트 지급 (군수담당자)
- **설명**: 산정된 포인트를 실제 지급 처리
- **처리**:
  1. `point_ledger`에 type='grant' 기록
  2. `point_summary`의 total_points 갱신
- **제약**: 해당 연도에 이미 지급된 경우 중복 지급 불가

### M5-3. 진급 포인트 추가 (군수담당자)
- **설명**: 사용자 진급 시 잔여기간 차액 추가 지급
- **산정 규칙**:
  1. 진급 전 계급 일일금액 = 구계급 연간금액 / 365
  2. 진급 후 계급 일일금액 = 신계급 연간금액 / 365
  3. 차액 = (신계급 일일금액 - 구계급 일일금액) × 잔여일수 (진급일~12월31일)
- **처리**: `point_ledger`에 type='add' 기록, `point_summary` 갱신

### M5-4. 포인트 현황 조회 (군수담당자)
- **설명**: 전체 사용자의 포인트 현황 조회
- **표시**: 이름, 계급, 총지급액, 사용액, 예약액, 잔액
- **필터**: 이름 검색, 계급, 소속

### M5-5. 내 포인트 조회 (일반사용자)
- **설명**: 본인의 포인트 현황 및 변동 이력 조회
- **표시**: 총지급액, 사용액, 예약액, 잔여액, 변동 이력 목록

## M6. 판매/구매 모듈

### M6-1. 오프라인 판매 (피복판매소)
- **설명**: 판매소에서 사용자에게 직접 판매
- **흐름**:
  1. 사용자 검색 (군번/이름)
  2. 사용자의 가용 포인트 확인: `잔여포인트 - 예약포인트`
  3. 품목 선택 (완제품/맞춤피복 별도)
  4. 완제품: 품목 + 규격 + 수량 선택
  5. 맞춤피복: 품목 선택 (수량 1 고정)
  6. 총액이 가용 포인트 이내인지 검증
  7. 판매 확정
- **처리 (완제품)**:
  1. `orders` 생성 (order_type='offline', status='delivered')
  2. `order_items` 생성
  3. `inventory` 재고 차감, `inventory_log` 기록
  4. `point_ledger` type='deduct' 기록, `point_summary` 갱신
- **처리 (맞춤피복)**:
  1. `orders` 생성 (order_type='offline', status='delivered')
  2. `order_items` 생성
  3. `tailoring_tickets` 체척권 발행 (status='issued')
  4. `point_ledger` type='deduct' 기록, `point_summary` 갱신
- **유효성**: 재고 부족 시 판매 불가 (완제품), 가용 포인트 초과 시 판매 불가

### M6-2. 오프라인 판매 내역 (피복판매소)
- **설명**: 해당 판매소의 오프라인 판매 내역 조회
- **필터**: 기간, 사용자명, 품목유형

### M6-3. 반품 처리 (피복판매소)
- **설명**: 오프라인 판매 건에 대한 반품
- **흐름**:
  1. 판매 내역에서 반품할 주문 선택
  2. 반품 항목/수량 선택
  3. 반품 확정
- **처리 (완제품)**:
  1. `order_items` 상태 변경 (returned)
  2. `inventory` 재고 추가, `inventory_log` 기록
  3. `point_ledger` type='add' 기록, `point_summary` 갱신
- **처리 (맞춤피복)**:
  1. 체척권 상태가 'issued'(미사용)인 경우만 반품 가능
  2. `tailoring_tickets` 상태 → 'cancelled'
  3. `point_ledger` type='add' 기록, `point_summary` 갱신
- **제약**: 맞춤피복은 체척권이 등록(registered)된 경우 반품 불가

### M6-4. 온라인 구매 (일반사용자)
- **흐름 (완제품)**:
  1. 쇼핑 메인에서 판매소를 먼저 선택 (필수)
  2. 선택한 판매소에 재고가 있는 완제품 목록 표시
  3. 품목 상세에서 해당 판매소의 재고 있는 규격만 표시
  4. 규격 선택 → 장바구니 담기 (store_id, store_name 포함)
  5. 장바구니에서 수량 조정(+/-) 및 품목 삭제 가능
  6. 구매할 품목 선택(체크박스) → [완제품 구매하기] 버튼
  7. 구매 확인 페이지: 배송방법 선택 (택배/직접배송)
     - 택배: 배송지 주소 직접 입력
     - 직접배송: 판매소 배송지 목록에서 선택
  8. 가용 포인트 확인 후 구매 확정
- **흐름 (맞춤피복)**:
  1. 쇼핑 메인에서 판매소 선택 불필요
  2. 맞춤피복 품목 목록 표시 (전체, 재고 무관)
  3. 품목 선택 → 장바구니 담기 (수량 1 고정, store 정보 없음)
  4. 장바구니에서 품목 삭제 가능 (수량 변경 불가)
  5. 구매할 품목 선택(체크박스) → [맞춤피복 구매하기] 버튼
  6. 구매 확인 페이지: 체척권 발행 안내만 표시 (배송 정보 없음)
  7. 가용 포인트 확인 후 구매 확정
- **장바구니 규칙**:
  - 완제품/맞춤피복 섹션 분리 표시
  - 섹션별 전체선택 체크박스 제공
  - 완제품: 수량 +/- 조정 가능, 판매소명 표시
  - 맞춤피복: 수량 1 고정 (조정 불가)
  - 섹션별 독립적인 [구매하기] 버튼 (선택된 항목만 checkoutItems로 전달)
- **처리**:
  1. `orders` 생성 (order_type='online', status='pending')
  2. `order_items` 생성
  3. 예약포인트 추가: `point_ledger` type='reserve', `point_summary.reserved_points` 증가
  4. 맞춤피복인 경우 체척권 발행 (배송 정보 저장 안 함)

### M6-5. 온라인 구매 취소 (일반사용자)
- **조건**: 배송 확정(delivered) 전까지만 취소 가능
- **처리**:
  1. `orders.status` → 'cancelled'
  2. 예약포인트 해제: `point_ledger` type='release', `point_summary.reserved_points` 감소
  3. 맞춤피복인 경우 체척권 취소 (미등록 시에만)

### M6-6. 온라인 주문 관리 (피복판매소)
- **설명**: 해당 판매소에 들어온 온라인 주문 관리
- **기능**: 주문 목록 조회, 상태별 필터 (대기/확인/배송중/완료/취소)
- **액션**: 주문 확인, 배송 처리, 직권 취소

### M6-7. 배송 처리 (피복판매소)
- **흐름**:
  1. 주문 확인 (status → 'confirmed')
  2. 재고 확인 → 배송 시작 (status → 'shipping')
  3. 배송 완료 확정 (status → 'delivered')
- **배송 확정 시 처리**:
  1. `inventory` 재고 차감, `inventory_log` 기록
  2. `point_ledger` type='deduct' (실제 차감)
  3. `point_ledger` type='release' (예약 해제)
  4. `point_summary`: used_points 증가, reserved_points 감소

### M6-8. 직권 취소 (피복판매소)
- **설명**: 재고 부족 등의 사유로 판매소에서 직접 주문 취소
- **조건**: 배송 확정 전 주문만 가능
- **처리**: M6-5 취소와 동일 + 취소 사유 기록

### M6-9. 구매 내역 조회 (일반사용자)
- **설명**: 본인의 온/오프라인 구매 내역 조회
- **표시**: 주문일, 주문유형, 품목, 금액, 상태, 배송상태
- **상세**: 주문 상세 페이지에서 품목별 정보, 배송 추적

### M6-10. 재고 현황 (피복판매소)
- **설명**: 판매소 내 품목별/규격별 현재 재고 조회
- **표시**: 품목명, 규격, 현재고, 최종변동일
- **필터**: 품목 분류, 재고 부족(임계값 이하)

### M6-11. 입고 처리 (피복판매소)
- **설명**: 신규 재고 입고 등록
- **입력**: 품목, 규격, 입고수량
- **처리**: `inventory` 수량 증가, `inventory_log` type='incoming' 기록

### M6-12. 재고 조정 (피복판매소)
- **설명**: 실사 등으로 재고 수량 조정
- **입력**: 품목, 규격, 조정수량(+/-), 조정사유
- **처리**: `inventory` 수량 변경, `inventory_log` type='adjust_up/adjust_down' 기록

### M6-13. 통계 (피복판매소)
- **일별 판매현황**: 기간별 일자별 판매금액/건수 집계
- **품목별 판매현황**: 품목별 판매수량/금액 집계
- **사용자별 판매현황**: 사용자별 구매금액/건수 집계

## M7. 체척권 관리 모듈

### M7-1. 체척권 발행
- **시점**: 맞춤피복 판매/구매 시 자동 발행
- **생성 데이터**: 체척권번호(자동), 사용자, 품목, 금액, 상태='issued'
- **출력**: 체척권 출력(인쇄) 기능

### M7-2. 체척권 취소 요청 (일반사용자/피복판매소)
- **조건**: 체척권 상태가 'issued'(미등록)인 경우만 가능
- **처리**: `tailoring_tickets.status` → 'cancel_requested'

### M7-3. 체척권 취소 승인 (군수담당자)
- **흐름**:
  1. 취소 요청된 체척권 목록 조회
  2. 체척권 등록 여부 확인 (등록 시 취소 불가)
  3. 취소 승인 처리
- **처리**:
  1. `tailoring_tickets.status` → 'cancelled'
  2. `point_ledger` type='return' 기록
  3. `point_summary.used_points` 감소 (포인트 복원)

### M7-4. 체척권 등록 (체척업체)
- **설명**: 체척업체에서 수령한 체척권 등록 (가공 시작)
- **입력**: 체척권번호
- **처리**: `tailoring_tickets.status` → 'registered', `tailor_id` 지정, `registered_at` 기록
- **제약**: 등록된 체척권은 취소 불가

### M7-5. 체척권 현황 조회
- **군수담당자**: 전체 체척권 목록, 상태별 필터
- **체척업체**: 자사 등록 체척권 목록
- **일반사용자**: 본인 체척권 목록

### M7-6. 체척업체 정산 (군수담당자)
- **설명**: 체척업체별 등록된 체척권 금액 정산
- **필터**: 기간, 업체
- **표시**: 업체별 등록 건수, 총금액, 정산상태
- **처리**: 정산 확정 시 `tailor_settlements` 기록

## 상태 전이도

### 주문(Order) 상태
```
[온라인]
pending → confirmed → shipping → delivered
pending → cancelled (사용자 취소)
confirmed → cancelled (직권 취소)

[오프라인]
delivered (즉시 완료)
delivered → returned (반품)
```

### 체척권(Tailoring Ticket) 상태
```
issued → registered (업체 등록, 취소 불가)
issued → cancel_requested → cancelled (취소 승인)
issued → cancel_requested → issued (취소 거부, 원상복구)
```
